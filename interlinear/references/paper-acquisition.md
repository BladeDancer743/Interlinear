# Paper acquisition

Use this reference for URLs, DOIs, PDFs, paywalled pages, or long papers.

## Source priority

Prefer sources in this order:

1. A file or excerpt supplied by the user.
2. The publisher's or conference's open HTML.
3. The paper's official arXiv HTML or abstract page.
4. ar5iv HTML for an arXiv paper.
5. An institutional or author-hosted preprint verified by matching title and authors.
6. PDF text extraction.

Do not assume a mirror is complete. Verify title, authors, and section numbering before using it.

## DOI and publisher pages

When the user gives a DOI or publisher URL:

1. Read the available metadata and abstract.
2. Search the exact title for an author manuscript or arXiv preprint.
3. Match both title and author list.
4. Tell the user which version is being used.
5. Link both the version of record and the accessible preprint when available.

Do not bypass access controls.

## PDF handling

Prefer a platform-native PDF reader or extraction tool. If local extraction is necessary, preserve page boundaries and watch for:

- missing ligatures;
- reordered columns;
- detached footnotes;
- flattened equations;
- lost superscripts and subscripts;
- figure captions separated from figures.

If extraction corrupts equations or structure, stop quoting the damaged text. Ask for the relevant page or use a reliable HTML source.

## Long-paper strategy

Treat a paper as long when it exceeds roughly 15 pages or 8,000 words.

1. Read the abstract, introduction, and conclusion to build the thesis map.
2. List the section structure.
3. Start with the section requested by the user; otherwise start with the abstract and introduction.
4. Carry a cumulative term registry across sections.
5. Deliver one coherent section at a time.

Do not fetch the whole paper into context when only one section is needed.

## Source record

Track:

```text
Title:
Authors:
Version/date:
Source used:
Version of record:
Scope annotated:
```

Include this record only when it helps disambiguate versions.
